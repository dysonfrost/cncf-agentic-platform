# Ollama on the host

Ollama runs on the host as a Docker container, not in the k3d cluster.
See ADR 0008 for the rationale: k3d does not support AMD GPU passthrough,
and gVisor (Agent Substrate) does not support AMD GPUs. Ollama therefore
runs on the host and uses the GPU directly via ROCm.

## Install

```bash
make ollama-install
```

This target is **Linux-only**. It generates `bootstrap/ollama/.env` from
the host's `video` and `render` group IDs, starts the container via
`compose.yaml`, and pulls `qwen3:8b`. On macOS, install Ollama natively
(Metal backend) and ensure it listens on port `11434`.

## Stop

```bash
make ollama-stop
```

The `ollama-models` volume persists; models are not re-downloaded.

## Verify

```bash
# List pulled models
curl -s http://localhost:11434/api/tags | jq '.models[].name'

# From inside the cluster
kubectl run test-ollama --image=curlimages/curl --rm -it --restart=Never -- \
  curl -s http://host.k3d.internal:11434/api/tags
```

`host.k3d.internal` is a DNS alias injected by k3d that resolves to the
host from inside the cluster.

## Configuration

- **GPU**: AMD RX 6700 XT (12 GiB), ROCm with `HSA_OVERRIDE_GFX_VERSION=10.3.0`
- **Model**: `qwen3:8b`, chosen for function calling over `llama3.1:8b`
- **Port**: `11434`, exposed to the cluster via `host.k3d.internal`
- **Memory**: `qwen3:8b` uses ~5-6 GiB of VRAM; `OLLAMA_KEEP_ALIVE=30m`
  keeps the model loaded 30 minutes after the last request
